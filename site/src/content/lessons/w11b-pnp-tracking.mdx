## 개념

이번 파트를 마치면 맵 포인트만 있으면 어떤 프레임의 자세든 구할 수 있다. 6주차 `pnpDLT`를 RANSAC으로 감싸고, 실제 영상에서 생기는 두 가지 문제(DLT의 수치 불안정, 대수적 오차)를 고친다.

### 3D-2D 추적

초기화 뒤 프레임마다 특징점 중 맵에 있는 id만 골라 (맵 포인트 $X$, 픽셀 $u$) 대응을 만든다. 이 대응으로 PnP를 풀면 그 프레임의 자세 $T_{cw}$가 맵과 같은 길이 단위로 나온다.

대응에는 엉터리가 섞인다. KLT 트랙이 비슷한 무늬로 미끄러지거나, 움직이는 물체 위의 점일 수 있다. 그래서 5주차 RANSAC으로 감싼다.

- **표본:** 대응 6개 (`pnpDLT`의 최소 개수)
- **모델:** `pnpDLT`로 구한 자세
- **오차:** 재투영 오차(픽셀). 점이 카메라 뒤로 가면 무한대
- **결과:** 가장 많은 대응이 맞는 자세와 그 inlier

inlier가 `minInliers`보다 적으면 추적 실패(`null`)다. 11c의 VO는 그 프레임에서 멈춘다(잃은 추적을 다시 잇는 재위치 인식(relocalization)은 이 과정 밖이다).

카메라가 제자리에서 돌기만 해도 맵 포인트가 보이는 동안은 PnP가 잘 풀린다. 순수 회전에서 무너지는 것은 새 점을 만드는 삼각측량(11a·11c)이지 추적이 아니다.

### 문제 1: DLT가 잡음에 매우 약하다

`pnpDLT`는 점 하나마다 $P$(12개 원소)에 대한 식 두 줄을 쌓고 $Ap = 0$을 푼다. 픽셀을 정규화 좌표 $(x, y)$로 바꿔 넣으므로, 식의 계수에는 $X, Y, Z, 1$과 $xX, xY, \ldots$가 섞여 있다.

맵 좌표가 원점에서 멀면 문제가 된다. 예를 들어 점들이 $z \approx 10$ 근처에 모여 있으면 $X, Y, Z$ 열은 10 안팎, 동차 성분 열은 1, $xZ$ 같은 곱 열은 5 안팎($x \approx 0.5$)이라 열 크기가 1과 10 정도로 벌어진다. 그러면 $A$의 조건수가 커져서(LA 박스) 작은 픽셀 잡음이 해를 크게 흔들고, 점이 6개뿐인 RANSAC 표본에서는 특히 심하다.

해결은 5주차 8점 알고리즘의 하틀리 정규화와 같은 생각이다. 3D 점을 무게중심 $\mu$로 옮기고 평균 거리 $d$로 나눈다. 5주차는 평균 거리를 $\sqrt 2$로 맞췄지만, 여기서는 1로 맞춘다.

$$
X' = (X - \mu) / d
$$

$X'$로 DLT를 풀어 $(R, t')$를 얻으면 원래 좌표의 자세는 $(R,\ d\,t' - R\mu)$다. 장면 전체를 $1/d$배 줄여도 사진은 같으므로 회전은 그대로이고 이동만 되돌리면 된다. 유도는 손 유도 1번에서 직접 한다.

이 레슨을 만들며 합성 장면으로 재 보니, 같은 프레임에서 RANSAC이 찾은 inlier가 정규화 없이 14개, 정규화하면 136개였다(대응 209개 중).

<LABox term="조건수와 데이터 정규화">
  **정의:** 행렬 $A$의 조건수 $\kappa(A) = \sigma_{\max} / \sigma_{\min}$(가장 큰 특이값 / 가장 작은 것). $Ax = b$에서 $b$의 상대 오차가 $x$에서 최대 $\kappa$배까지 커질 수 있다.

  **기하학적 의미:** $A$가 어떤 방향은 크게, 어떤 방향은 아주 작게 늘린다는 뜻이다. 작게 늘리는 방향의 정보는 잡음에 묻힌다. $Ap = 0$처럼 가장 작은 특이값 방향을 해로 찾을 때는, 가장 큰 특이값에 비해 둘째로 작은 특이값이 작을수록(가장 작은 것과의 간격이 좁을수록) $\kappa$가 클 때처럼 해가 잡음에 흔들린다.

  **SLAM에서:** 8점 알고리즘(5주차), PnP·삼각측량 DLT(6주차)는 모두 입력 좌표를 원점 근처, 크기 1 정도로 옮긴 뒤 풀고 결과를 되돌린다. 변수의 단위를 맞추는 것(픽셀 대신 정규화 좌표, 미터 대신 평균 거리)도 같은 목적이다.

  **이전 레슨:** [2주차 최소제곱과 SVD](../w02-least-squares-svd/)
</LABox>

### 문제 2: DLT는 재투영 오차를 줄이지 않는다

DLT는 $|Ap|$, 즉 대수적 오차를 최소화한다. 우리가 원하는 것은 재투영 오차(픽셀)의 최소화다. 둘은 잡음이 있으면 다른 답을 준다.

그래서 RANSAC이 찾은 자세에서 시작해 **자세만** 7a의 LM으로 다듬는다. 점은 고정이라 변수는 6개뿐이다.

- **잔차:** inlier마다 $[u - u_\text{관측},\ v - v_\text{관측}]$
- **야코비안:** 8a `projectionJacobian`의 `pose` 블록 (2×6)
- **업데이트:** $\delta = [\rho;\ \phi]$(이동 먼저, 8a 야코비안의 열 순서와 같다)로 좌섭동 $R \leftarrow \mathrm{Exp}(\phi)R$, $t \leftarrow \mathrm{Exp}(\phi)t + \rho$ (7b)

다듬은 자세로 inlier를 다시 센다. 처음에 경계에 걸려 빠졌던 점이 들어오기도 한다. 이 (다듬기 → 다시 세기)를 두 번 한다. ORB-SLAM의 `PoseOptimization`이 같은 일을 하는데, 거기서는 다듬을 때마다 아웃라이어를 다시 판정하며 네 번 돈다.

### 실무 PnP

OpenCV `solvePnPRansac`은 DLT 대신 최소 3~4점으로 푸는 방법을 표본에 쓴다. P3P(원근 3점 문제)는 점 3개로 자세 후보를 구하고, EPnP(효율적 PnP)는 점들을 제어점 4개의 가중합으로 나타내 한 번에 푼다. 표본이 작을수록 RANSAC 반복이 적게 필요하고, 평면 장면에서도 잘 된다(DLT는 점들이 한 평면 위면 퇴화한다).

그 뒤 LM으로 다듬는 순서는 같다. 12주차 C++ 포팅에서 이 함수를 쓴다.

### 손 유도: 정규화 되돌리기, 반복 수

태블릿에 직접 쓴다.

1. $X' = (X - \mu)/d$에서 구한 자세 $(R, t')$를 원래 좌표의 자세로 되돌리는 식 $t = d\,t' - R\mu$를 유도한다. ($p_c = d\,(RX' + t')$에서 시작한다. 왜 $d$를 곱해도 사진이 같은가?)
2. 대응의 30%가 엉터리일 때, 6점 표본이 전부 inlier일 확률은? 99% 확률로 좋은 표본을 한 번 이상 뽑으려면 몇 번 뽑아야 하나? 3점 표본(P3P)이면?
3. 자세만 다듬을 때 변수는 몇 개이고, inlier가 100개면 잔차는 몇 개인가? $J^\top J$의 크기는?
4. 맵 포인트가 모두 한 평면($Z = 5$) 위에 있으면 PnP DLT가 왜 퇴화하는지 생각해 본다. ($P$의 셋째 열이 무엇과 곱해지는가?)

<TaskCard fn="trackPnP">
  맵 포인트(`map`, id와 월드 좌표)와 현재 프레임 특징점(`features`)을 id로 이어 현재 자세 $T_{cw}$를 구한다. 결과는 `{ T, inliers }`이고 `inliers`는 특징점 id 오름차순이다. 맵과 겹치는 특징점이나 최종 inlier가 `minInliers`보다 적으면 `null`이다. `K`가 이상하거나, 같은 id가 두 번 있거나, 좌표가 NaN·무한대이거나, `threshold ≤ 0`이거나 `minInliers < 6`이면 예외를 던진다.

  <Hint level={1}>
    RANSAC 표본은 6개, 모델은 `pnpDLT`, 오차는 재투영 오차다. `pnpDLT`에 넣기 전에 3D 점을 정규화하고, 나온 자세를 되돌린다. 마지막에 자세만 LM으로 다듬는다.

    ```ts
    import { expSO3 }
      from "@core/prev/w03";
    import { ransac }
      from "@core/prev/w05";
    import { pnpDLT }
      from "@core/prev/w06";
    import { levenbergMarquardt }
      from "@core/prev/w07";
    import { projectionJacobian }
      from "@core/prev/w08";
    ```
  </Hint>

  <Hint level={2}>
    `fit(표본)`: $\mu$ = 표본 3D 점의 평균, $d$ = $\mu$까지의 평균 거리. $d = 0$이면 `null`. `pnpDLT`에 $(X - \mu)/d$와 정규화 좌표를 넣고, 예외면 `null`. 되돌린 자세는 $(R,\ d\,t' - R\mu)$.

    자세 다듬기는 7a `levenbergMarquardt<SE3>`에 `{ residual, jacobian, plus }`를 넘긴다. 8b `smallBA`에서 카메라 하나만 남기고 점을 뺀 모양이다. 카메라 뒤로 간 점은 잔차를 크게(예: $10^6$) 두고 야코비안은 0으로 둔다. 설정은 반복 10번, 허용 오차 $10^{-10}$이다.
  </Hint>

  <Hint level={3}>
    ```text
    검사 (K, 같은 id, NaN,
      threshold, minInliers ≥ 6)
    corr ← features 중 map에
      있는 id의 { id, X, uv }
    corr 수 < minInliers
      이면 null
    fit(표본):
      μ ← 표본 X의 평균
      d ← μ까지 평균 거리
      (R, t') ← pnpDLT(
        (X − μ)/d, 정규화 uv)
        (예외면 null)
      { R, t: d·t' − Rμ }
    err(T, c) ← 재투영 오차
      (카메라 뒤면 ∞)
    found ← ransac(corr, {
      sampleSize: 6, fit,
      error: err, threshold,
      iterations, rng })
    found 없음 이면 null
    T ← found.model
    inl ← found.inliers
    두 번 반복:
      T ← 자세 다듬기(T,
        inl의 대응)
      inl ← err(T, c)
        < threshold 인 c
    inl 수 < minInliers
      이면 null
    { T, inliers:
      inl의 id 오름차순 }
    ```
  </Hint>

### trackPnP 테스트가 안 맞을 때

- 기본 테스트(30%가 엉터리)에서 inlier가 50개보다 적게 나오면 3D 점 정규화를 빼먹었을 가능성이 크다. 시험 장면의 점은 $z = 6 \sim 14$에 모여 있어서 정규화 없이는 좋은 표본이 드물다.
- 자세 오차만 조금 넘으면 자세 다듬기를 빠뜨렸거나, `plus`의 섭동이 8a 야코비안과 다르다(우섭동으로 썼거나 $t$에 $\mathrm{Exp}(\phi)$를 곱하지 않음).
- "맵에 없는 id는 무시" 테스트가 실패하면 대응을 만들 때 `map`에 없는 특징점을 걸렀는지 본다.
- `inliers`에 대응 번호(0, 1, 2, …)가 들어가면 안 된다. 특징점 id로 바꿔서 돌려준다.

## 체크 질문

<CheckQuestion q="초기화 뒤에는 왜 2D-2D(E 분해) 대신 3D-2D(PnP)로 자세를 구하나?" kind="개념">
  PnP는 맵 포인트의 3D 좌표를 쓰므로, 구한 자세가 맵과 같은 길이 단위로 나온다. 모든 프레임이 하나의 맵을 기준으로 하니 궤적이 이어진다.

  2D-2D는 쌍마다 이동 크기가 1로 정해져 단위가 제각각이고, 순수 회전에서는 $E$ 자체가 퇴화한다. PnP는 맵이 보이는 동안 순수 회전에서도 잘 풀린다.
</CheckQuestion>

<CheckQuestion q="PnP DLT 전에 3D 점을 정규화하지 않으면 왜 RANSAC이 좋은 자세를 잘 못 찾나?" kind="왜">
  점이 원점에서 멀면 DLT 행렬 $A$의 열 크기가 크게 달라 조건수가 커진다. 6점짜리 표본은 잡음에 특히 약해서, 모두 inlier인 표본으로 맞춘 자세도 다른 점들의 재투영 오차가 기준을 넘는다. 그래서 inlier가 적게 세어지고 엉뚱한 표본이 이길 수 있다.

  평균 0, 평균 거리 1로 옮기면 열 크기가 비슷해져 같은 표본으로 훨씬 정확한 자세가 나온다. 자세는 정확히 되돌릴 수 있으므로 손해가 없다.
</CheckQuestion>

<CheckQuestion q="실제 영상에서 VO가 몇 프레임마다 자세가 툭툭 튄다. trackPnP에서 무엇을 확인하나?" kind="실무">
  inlier 수와 비율을 프레임마다 찍어 본다. 비율이 갑자기 떨어지는 프레임이 튀는 곳이면, 맵에 잘못된 점(미끄러진 트랙)이 쌓였거나 모션 블러로 트랙이 흔들린 것이다. 11c에서 아웃라이어로 판정된 맵 포인트를 지우는 정리를 넣는다.

  자세 다듬기가 실제로 비용을 줄이는지(LM의 cost), 재투영 기준(픽셀)이 데이터에 맞는지도 본다. TUM 같은 실제 데이터는 롤링 셔터와 보정 오차 때문에 합성 데이터보다 넉넉한 기준(5~6px)이 필요했다(11d).
</CheckQuestion>
