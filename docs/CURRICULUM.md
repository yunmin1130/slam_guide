# CURRICULUM

핵심 경로는 0~11주차(미니 VO)와 12~17주차(지원 병행)다. "주"는 레슨 번호이고, 실제 소요는 **단위(1단위 = 약 5시간)**로 따로 적는다.

## 일정 (정직한 추정)

- 미니 VO 완성(마일스톤 **M1**)까지 약 24단위 ≈ 120시간. 육아 공백으로 실제 공부하는 주가 70~75%라고 보면 **달력으로 약 8개월**.
- 전체(캡스톤 포함, 선택 항목 제외) 약 39단위 → **달력으로 13~14개월**.
- **지원 시작은 주차가 아니라 M1 기준**이다: 정답 궤적이 있는 공개 데이터셋(TUM RGB-D, 2026-11-03 선택)에서 TS 미니 VO + ATE/RPE 리포트가 사이트에 공개된 시점. JetBot 데이터 결과는 M1의 보너스다. C++ 포팅(12주차)은 지원과 병행한다.
- 레슨마다 실제 소요 시간을 기록하고, 3레슨마다 이 추정을 다시 맞춘다.

## 범례

- **데모 ✅**: 인터랙티브 데모를 만드는 주차
- **손코딩**: `core/mine`에 직접 구현할 함수 (면접 핵심 위주)
- **읽기만**: reference를 읽고 테스트만 돌려보는 함수 (손코딩 안 함)
- **LA 박스**: 이번 주에 필요한 선형대수·확률 개념
- **🤖 JetBot**: 실데이터 주차. JetBot 환경이 막히면 **iPhone 0.5× 초광각 영상 + 공개 데이터셋**으로 대체한다 (DATA §4)
- **PC Python**: 무거운 영상 처리(캘리브레이션, 특징점 추출·매칭)는 PC Python OpenCV로 하고 결과를 JSON으로 내보낸다. 브라우저는 시각화와 수학만 한다.

## 주차별 상세

### 0주차 — 플랫폼 뼈대
- AI가 주도하고 PC에서만 한다. 체크리스트는 `docs/TASKS.md`.
- 최소 범위만 만든다. Gist 동기화, 3D 터치 조작, 비교 오버레이는 필요해지는 주차에 붙인다.

### 1주차 — 선형대수 ①
- **LA1 레슨 하나를 끝까지 완성**하고 이를 템플릿으로 삼는다.
- 반대칭 행렬(`skew`)은 이후 회전·Lie·에피폴라·야코비안에 계속 나오므로 확실히 잡는다.

### 2주차 — 선형대수 ② (처음부터 2단위)
- 8점 알고리즘, 삼각측량, PnP는 **"SVD로 Ax=0 풀기"**다. 궤적 정렬(Umeyama)은 다른 유형인 **공분산 행렬의 SVD(Procrustes)**다. 둘을 구분해서 배운다.
- 함정: 8×9처럼 가로로 긴 행렬은 thin SVD에서 영공간 벡터가 안 나올 수 있다 (LESSON_TEMPLATE §4).

### 3주차 — 회전, SE(3), Lie 기초 (2단위)
- 3a: 회전행렬·쿼터니언 / 3b: SE(3) 합성·역, exp/log.
- `expSO3`/`logSO3`는 θ→0, θ→π 경계 처리를 테스트로 확인한다. 7주차 섭동 모델의 기반이다.

### 4주차 — 카메라 모델
- 카메라 엔진 경험이 가장 빛나는 주차.
- JetBot 카메라(IMX219-160)는 160° 광각이라 핀홀 모델로 맞지 않는다. 캘리브레이션은 PC Python(`cv2.fisheye.calibrate`)으로 하고, 결과 JSON을 사이트에서 핀홀 모델과 재투영 오차로 비교한다.
- `distort`/`undistort`는 핀홀(Brown) 모델이다. 어안(Kannala-Brandt) 픽셀 → 방향 벡터 변환은 `unprojectFisheye`(읽기만)로 제공하고 5주차에서 쓴다.

### 5주차 — 에피폴라
- 대응점은 PC Python에서 미리 추출·매칭한 JSON을 쓴다 (블랙박스). 매칭 원리는 10주차에 다룬다.
- 어안 이미지는 픽셀 좌표가 아니라 **`unprojectFisheye`로 만든 방향 벡터(bearing vector)**로 E를 추정한다. 어안 원본에서는 에피폴라선이 곡선이라, 에피폴라선 데모는 핀홀 데이터셋이나 왜곡 보정된 이미지로 한다.
- 5점 알고리즘은 개념만 언급한다 (실무 표준, 최소 표본).
- 호모그래피(H)도 개념으로 언급한다: 평면 장면이나 순수 회전에서는 E 대신 H가 맞는 모델이다 (11주차 초기화에서 다시 쓴다).

### 6주차 — E 분해, 삼각측량, PnP
- `decomposeE`: 4개 해 중 두 카메라 앞에 점이 오는 해(cheirality)를 고른다. 삼각측량의 전제.
- `pnpDLT`는 최소 6점이 필요하고 노이즈에 약하다. 실무 표준인 EPnP·P3P+RANSAC은 개념으로 다룬다.

### 7주차 — 최적화와 매니폴드
- 7a: GN, LM, Huber. `levenbergMarquardt`는 `gaussNewton`에 감쇠 λ를 더한 것이라 읽기만 한다.
- 7b: SE(3) 위의 업데이트 x ⊞ δ, 섭동 모델. `numericJacobian`으로 해석 야코비안을 검증하는 습관을 여기서 만든다.
- **섭동 규약 (전 과정 공통)**: 좌섭동 T ← exp(δ^)·T, δ = [ρ; φ] (평행이동 먼저). 이 규약에서 ∂(Rp)/∂δφ = −[Rp]×. 우섭동(T·exp(δ^))이면 −R[p]×가 되므로 섞지 않는다. 8주차 `projectionJacobian`, 11주차 `localBA`도 이 규약을 따른다.

### 8주차 — 번들 조정
- 8a: `projectionJacobian` (재투영 오차의 포즈·점 야코비안, `numericJacobian`과 비교하는 테스트).
- 8b: `smallBA` 루프. 희소성과 Schur는 개념 + 데모로.

### 9주차 — 포즈 그래프 + 루프 클로저
- 포즈 그래프의 루프 엣지가 어디서 오는지까지 다룬다: BoW(DBoW2) 장소 인식 → 기하 검증(PnP/Sim(3)) → 루프 엣지 추가.
- 장소 인식은 개념만, 직접 구현은 미룬다. "VO와 SLAM의 차이"를 이 주차 체크 질문으로 다룬다.

### 10주차 — 특징점·매칭 원리
- ORB 같은 바이너리 디스크립터는 **해밍 거리**, SIFT 같은 실수 디스크립터는 L2(또는 코사인)를 쓴다.
- 추출·매칭은 PC Python, `ratioTest`만 직접 구현한다.

### 11주차 — 미니 VO (4.5단위, M1)
- 11a `initMap`: 2D-2D 초기화(`eightPoint`+`decomposeE`) → 삼각측량으로 맵 포인트 생성. **시차 검사**: 두 프레임 사이 시차가 임계값보다 작으면(순수 회전·정지) 초기화를 미룬다.
- 11b `trackPnP`: 이후 프레임은 **맵 포인트 대상 3D-2D PnP+RANSAC 추적**. 순수 회전 구간에서는 새 점을 삼각측량하지 않고 추적만 유지한다.
- 11c `localBA`: 키프레임마다 local BA (`smallBA` 재사용). `vo`는 이 셋을 조립하는 함수로 읽기만 한다.
- 11d 평가: 단안이라 스케일이 없으므로 ATE·RPE 모두 **Sim(3)**(스케일 포함 Umeyama) 정렬 후 계산한다.
- 데이터: M1 리포트는 **TUM RGB-D**로 낸다 (2026-11-03 선택: 시퀀스별 다운로드, 모션캡처 정답, 깊이로 스케일 대조, JetBot과 같은 실내). 디버깅은 `fr1/xyz`, 리포트는 `fr1/desk` 또는 `fr3/long_office_household`. KITTI는 12주차 C++ 포팅·캡스톤 확장. JetBot 데이터(출발점 복귀 오차, 사각형 경로)는 보너스.
- 체크 질문: ① 2D-2D만 반복하면 왜 궤적이 이어지지 않나 ② 순수 회전에서 E 분해·삼각측량이 왜 무너지나, ORB-SLAM은 H와 E 중 어떻게 고르나.
- (선택, 지원서용) "노출 고정 vs 자동" 미니 실험 하나: 캡스톤 주제의 예고편.

### 12주차 — C++ 포팅 (지원과 병행)
- **12a (필수, 4단위)**: 환경 세팅(WSL2 Ubuntu 22.04 또는 Docker, 상한 1단위) → C++17 + Eigen + OpenCV로 KITTI 단안 VO 포팅 (특징점·PnP는 OpenCV API 사용) → `evo`로 ATE/RPE → CMake, GTest, GitHub Actions CI. 결과는 TS 사이트에 쇼케이스로 시각화한다.
- **12b (선택, 2단위)**: 자기 VO의 local BA를 Ceres로 다시 푼다 (AutoDiff + `Manifold`로 SE(3) 파라미터화). 2D 포즈 그래프보다 면접 설명 가치가 크다.
- (선택) ROS2 노드로 감싸서 rosbag 재생과 RViz 시연.
- 산출물은 함수가 아니므로 레슨 frontmatter의 `deliverables`에 적는다.

### 14주차 — IMU, VIO
- MSCKF와 IMU 사전적분(preintegration)은 개념 한 줄씩.
- 롤링셔터·IMU 퓨전에는 카메라-IMU 시간 오프셋 보정(Kalibr)이 필요하다는 점을 메모한다.

### 15주차 — 직접법·스테레오·주변화 (개념)
- 직접법 vs 특징점 방식 (DSO), 스테레오의 스케일 관측성, 슬라이딩 윈도우 주변화(8주차 Schur와 연결).
- DSO의 photometric calibration(응답곡선, 비네팅, 노출시간)은 캡스톤의 이론적 배경이다.

### 16주차 — 코드 리딩
- ORB-SLAM3는 Docker 이미지로 받아 빌드 문제를 피한다.

### 17주차~ — 캡스톤
주제: **카메라 특성이 Visual Odometry 정확도에 주는 영향**

- **회전 속도를 바꿔 주행** → 롤링셔터 왜곡과 모션 블러의 영향 (롤링셔터 효과는 직진보다 회전에서 크게 드러난다)
- **조명 조건 변경** (불 켜고 끄기, 창가 역광) → 자동 노출 변화가 특징점 추적에 주는 영향
- **노출 수동 고정 vs 자동** (`nvarguscamerasrc` 설정)
- 기준 궤적: (ROS 선택 트랙) 라이다 SLAM 결과 / (기본) 공개 롤링셔터 데이터셋(예: TUM RS-VIO)으로 보강
- 결과는 인터랙티브 리포트 레슨으로 정리한다.
- 회사 코드나 내부 데이터는 절대 쓰지 않는다. 공개 데이터셋과 직접 수집한 데이터만 사용한다.
