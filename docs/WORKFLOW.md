## 1. 전체 단계

| 단계 | 내용 | 완료 조건 |
| --- | --- | --- |
| A | 커리큘럼 검토 | 완료 — G0 1·2차 2026-10-31, 조건부 통과 항목 반영 |
| B | 0주차 플랫폼 뼈대 | `docs/TASKS.md` 체크리스트 전부 완료 (G1 통과 포함). 손코딩은 1주차에서 시작 |
| C | 주차별 레슨 | `docs/LESSON_TEMPLATE.md` §5 흐름 + 아래 관문 통과 |

## 2. 검토 관문

검토는 **관문에서만** 한다. 매 세부 단계마다 하지 않는다. 사용자 시간은 손코딩에 우선 배정한다.

| 관문 | 시점 | 에이전트 | 확인할 것 |
| --- | --- | --- | --- |
| G0 | 커리큘럼 검토 (A단계, M1) | 범용 3개 병렬 | ① SLAM 도메인·이직 시장: 빠진 주제, 순서, M1 결과물의 포트폴리오 가치 ② 학습 부하: 단위 추정의 현실성, 분할할 주차 ③ 실행 리스크: 플랫폼 범위, 라이브러리, 환경, 문서 간 불일치 |
| G1 | 플랫폼 뼈대 완료 직후 | `architect` | `impl.ts`가 유일한 mine/reference 분기점인지, `storage.ts`가 유일한 저장 진입점인지, 데모가 core를 직접 import하지 않는지, 모바일 원칙(ARCHITECTURE §8) 준수 |
| G2 | 레슨 하나 생성 완료마다 | 아래 4개 (리뷰 3개는 병렬) | 4개 모두 CRITICAL·HIGH가 없어야 커밋한다 |
| G2-math | 〃 | `code-reviewer` | `core/reference` 수학적 정확성(경계값을 스크립트로 직접 넣어 확인), `core/tests` 케이스 충분성(함수당 기본·경계·수치 3개 이상, 허용 오차 명시, 흔한 오구현을 잡는지), `core/mine`에 구현 코드가 섞이지 않았는지, frontmatter `tasks`와 함수명 일치 |
| G2-qa | 〃 | 스크립트 `npm run build && npm run qa` | 393px·라이트/다크에서 수식 렌더 오류, 가로 넘침, 콘솔 오류, 과제 카드, 코드 연습장 채점 실행, 데모 그림 높이 400px·토글. 실패 0이어야 한다 |
| G2-read | 〃 | `lesson-learner` (`.claude/agents/`) | 학습자 입장 읽기: 설명 없는 용어, 건너뛴 논리, 손 유도가 풀리는지, 표기 일관성, 템플릿 문체 규칙 |
| G2-visual | G2-qa 다음 | `lesson-visual-qa` (`.claude/agents/`) | `qa-output/*.png`를 보고 겹침·잘림·다크 대비·작은 터치 영역 |
| G3 | **데모가 있는 주차만** | 없음 (사용자가 폰에서 2분) | 실제 iPhone Safari에서 데모를 손가락으로 조작 (회전·슬라이더·토글). 자동 검사로 못 보는 터치 감각만 확인한다. 데모 없는 주차는 G3 없음 (2026-11-02 결정) |
| G4 | 커밋 전 (코드 변경 시) | `code-reviewer` | 변경 파일 범위 내 품질. reference 테스트 통과가 선행 조건. 사이트 화면이 바뀌는 변경이면 `npm run qa`도 통과 |

### 관문 처리 규칙

- 에이전트 결과 중 CRITICAL·HIGH만 즉시 수정한다. MEDIUM 이하는 사용자에게 목록으로 보여주고 판단을 맡긴다.
- G2에서 reference 오류가 나오면 **mine 작업보다 먼저** 고친다. reference가 틀리면 사용자의 mine 구현을 틀린 기준으로 검증하게 된다.
- 에이전트가 "커리큘럼 자체를 바꾸자"고 제안하면 바로 고치지 않고 사용자에게 묻는다.

## 3. 하지 않는 검토

- `core/mine`: 사용자의 학습 영역. 사용자가 요청할 때만 리뷰한다. 요청 없이 수정하지 않는다.
- 레슨 본문 문체·분량: 생성 시 `LESSON_TEMPLATE.md` §3·§6에 맞추고, G2-read가 학습자 입장에서 한 번 읽는다. 그 밖의 별도 문체 리뷰는 하지 않는다.
- 사용자 화면 확인: 데모 없는 주차는 사용자 확인을 기다리지 않고 다음으로 넘어간다. 사용자가 읽다가 걸리는 것을 말하면 그때 고친다.
- 매 함수·매 파일 단위 리뷰: 하지 않는다. 레슨 단위(G2)로 묶는다.

## 4. 세션 시작 시

1. `git log --oneline -5`, `docs/TASKS.md`, `core/tests` 실패 목록으로 현재 위치 확인
2. 몇 주 쉬었다 돌아온 경우에도 질문 없이 다음 할 일을 제시할 수 있어야 한다
3. 진행 중이던 관문이 있으면 그것부터 마친다
